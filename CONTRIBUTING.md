# Contributing to QualityFlow

## Adding a New Project

Preferred: generate the config from the template:

```bash
cp onboarding-template.yaml my-project.yaml
# fill in the required fields, then preview:
uv run onboard.py --input my-project.yaml --dry-run
# apply (writes config/projects/<id>/ and the routing.yaml entry):
uv run onboard.py --input my-project.yaml
```

Or by hand:

1. Copy the example skeleton:
   ```bash
   cp -r config/projects/example config/projects/yourproject
   ```
2. Edit the YAML files to match your project (Jira instance, repositories, components, test patterns)
3. Add a route in `config/routing.yaml`
4. Validate: `python config/validate.py config/projects/yourproject/`

Either way, finish with a deploy preview: `uv run deploy.py --target claude --dry-run`

## Adding a New Skill

1. Create `skills/your-skill/SKILL.md` with YAML frontmatter (`name`, `description`, `version`)
2. Define inputs, outputs, and behavior
3. Reference from an agent or command that uses it
4. Run CI: the `lint-specs` job verifies SKILL.md presence and frontmatter

## Adding a New Agent

1. Create `agents/your-agent.md` with YAML frontmatter
2. Define the agent's role, tools, and orchestration logic
3. Reference from a command or orchestrator agent

## Adding a New Command

1. Create `commands/your-command.md` with YAML frontmatter
2. Define the user-facing interface and which agents/skills it invokes

## Local Testing

```bash
# Validate all project configs against schema
python config/validate.py config/

# Validate a single project
python config/validate.py config/projects/yourproject/

# Dry-run deployment (preview what gets copied)
uv run deploy.py --dry-run --target claude

# Validate + deploy
uv run deploy.py --target claude --validate
```

## Pull Request Workflow

1. Fork and branch from `main`
2. Make changes in `agents/`, `commands/`, `skills/`, or `config/`
3. Run `python config/validate.py config/` if config changed
4. Run `uv run deploy.py --dry-run --target claude` to verify deployment
5. Open a PR — CI runs config validation, deploy dry-run, and spec linting automatically

## Source of Truth

| Directory | Purpose | Edit here? |
|-----------|---------|------------|
| `agents/` | Agent definitions | Yes |
| `commands/` | Slash command definitions | Yes |
| `skills/` | Skill definitions | Yes |
| `config/` | Project configuration | Yes |
| `.claude/`, `.cursor/` | Deployment targets (generated by `deploy.py`) | No |
