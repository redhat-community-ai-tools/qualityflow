# TC-E2E-003: Disconnected deployment to inference end-to-end

**Objective**: Validate the complete user journey of deploying and
using vLLM-Omni in a disconnected/air-gapped OpenShift environment
from image mirroring through successful inference.

**Preconditions**:

- Disconnected OpenShift cluster with no external internet access
- Local container registry with mirrored vLLM-Omni image
- ImageContentSourcePolicy or ImageDigestMirrorSet configured
- Model weights in local S3 (MinIO) mirrored for disconnected cluster (Qwen3-Omni-30B-A3B
  weights pre-loaded in the MinIO models bucket)
- RHOAI operator installed with vLLM-Omni template
- `HF_HOME=/tmp/hf_home` set in the ServingRuntime template

**Test Steps**:

1. Via `pod.execute(command=["skopeo", "inspect",
   "docker://<mirror-registry>/<rhaii-namespace>/vllm-omni-cuda-rhel9@<sha256-digest>"])`,
   verify the mirrored image is available in the local registry.
2. Via `create_isvc(client=admin_client, name=..., namespace=...,
   runtime=omni_serving_runtime, storage_uri=...,
   resources=OMNI_PREDICT_RESOURCES)`, deploy an InferenceService using the
   vLLM-Omni runtime.
3. Via `Pod.get_events()`, monitor the pod for image pull and initialization
   events.
4. Via `pod_is_ready(pod=omni_pod_resource)` with `TimeoutSampler`
   (timeout=600s), wait for the pod to reach Ready state.
5. Via `OpenAIClient.get("/health")`, assert the response status code == 200.
6. Via `OpenAIClient.post(endpoint="/v1/audio/speech",
   body={"model": "Qwen3-Omni-30B-A3B",
   "input": "This inference is running in a disconnected OpenShift environment.",
   "voice": "vivian"})`, send a TTS inference request. Assert the response
   returns HTTP 200 with a non-empty audio body.
7. Via `Pod.get_logs()`, verify pod logs show no external network access
   attempts, DNS failures, or download errors.

**Expected Results**:

- The pod pulls the image from the mirrored registry, not from
  `registry.redhat.io`
- Pod reaches Ready state without external network access
- `/health` returns HTTP 200
- Inference request returns HTTP 200 with valid audio output
- Pod logs contain no download errors, DNS failures, or external
  connection attempts
- The entire deployment-to-inference workflow succeeds in the
  air-gapped environment
