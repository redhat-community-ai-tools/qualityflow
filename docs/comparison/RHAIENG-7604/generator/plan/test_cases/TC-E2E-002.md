# TC-E2E-002: CLI fallbacks for absent source ownership fields

**Objective**: Verify that the CLI fallback flags supply absent tenant and owner-subject
values while the fixed ownership issuer is still written to every target row.

**Preconditions**:

- A cluster-admin test identity can invoke the migration CLI or Job and inspect both source
  and target datastores.
- The supported CLI executable, command or subcommand, target-row query method, and fixture
  schema have been confirmed for the test environment.
- The exact meaning of an absent source field has been confirmed for this run. This case uses
  an absent field, not an explicitly empty or whitespace-only value.
- The same fixture and assertions are executed against the selected pre-upgrade and
  post-upgrade deployments; exact versions remain an open plan gap.
- The target datastore is isolated from prior runs, or the fixture rows have unique identifiers
  that allow their migrated rows to be selected without including unrelated data.

**Test Steps**:

1. Create two source rows using the supported fixture mechanism:
   - Row A has no `tenant_id` and has `owner_principal=principal-batch-01`.
   - Row B has `tenant_id=tenant-analytics-01` and no `owner_principal`.
2. Run the supported OGX DB migration CLI command or Job with
   `--fallback-tenant=tenant-fallback-01` and
   `--fallback-owner-subject=subject-fallback-01`.
3. Wait for the migration completion signal and collect the command or Job output.
4. Inspect the Praxis target rows corresponding to Row A and Row B.
5. Compare each target field with the source or fallback value that applies to that row, and
   inspect `owner_issuer` on every migrated target row.

**Expected Results**:

- The migration command or Job reports successful completion.
- Row A's target `tenant_id` equals `tenant-fallback-01`.
- Row A's target `owner_subject` equals `principal-batch-01`.
- Row B's target `tenant_id` equals `tenant-analytics-01`.
- Row B's target `owner_subject` equals `subject-fallback-01`.
- Every migrated target row has `owner_issuer` equal to
  `urn:rhoai:ogx:production`.

**Test Data**:

```yaml
rows:
  - fixture_label: missing-tenant-row
    tenant_id: absent
    owner_principal: principal-batch-01
  - fixture_label: missing-owner-row
    tenant_id: tenant-analytics-01
    owner_principal: absent
fallback_tenant: tenant-fallback-01
fallback_owner_subject: subject-fallback-01
owner_issuer: urn:rhoai:ogx:production
```

Map these logical fields to the supported source-fixture schema once the fixture contract is
confirmed.

**Validation**:

- Use the supported target-datastore inspection method to select only rows created from the
  fixture and verify the direct, fallback, and fixed-issuer values above.
