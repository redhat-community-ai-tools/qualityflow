# TC-E2E-002: End-to-end alert firing and dashboard correlation

**Objective**: Validate the full alert pipeline: sustained high
deny ratio triggers `MaaSHighAuthDenyRate` alert, and the alert
state is visible in both the Prometheus alerts API and the
dashboard context.

**Preconditions**:

- ServiceMonitor, PrometheusRule, and Perses dashboard applied
- No pre-existing `MaaSHighAuthDenyRate` alerts
- Auth traffic flowing with >10% deny ratio

**Test Steps**:

1. Generate auth traffic with approximately 25% deny rate for
   15 minutes.
2. After 10 minutes, check alert state (should be transitioning
   to `firing`):

   ```bash
   curl -s "https://<prometheus-route>/api/v1/alerts" | \
     jq '.data.alerts[] | select(.labels.alertname ==
     "MaaSHighAuthDenyRate") | {state, labels, annotations}'
   ```

3. After 15 minutes, verify the alert is in `firing` state.
4. Verify the dashboard "Deny ratio by policy" panel shows
   the elevated deny ratio:

   ```bash
   curl -s "https://<prometheus-route>/api/v1/query?query=\
     maas:auth_deny_ratio:rate5m" | jq '.data.result[]'
   ```

5. Stop generating denied traffic (send only valid requests).
6. After 10 minutes of clean traffic, verify the alert resolves
   (transitions to `inactive`).
7. Verify the dashboard deny ratio drops back toward 0.

**Expected Results**:

- `MaaSHighAuthDenyRate` alert fires after 10+ minutes of
  sustained >10% deny rate
- Alert annotations reference the specific authconfig hash and
  namespace
- Dashboard "Deny ratio by policy" panel correlates with alert
  state — showing elevated ratio during firing
- Alert resolves within 10 minutes after deny rate drops below
  threshold
- Dashboard deny ratio returns to approximately 0 after
  resolution
