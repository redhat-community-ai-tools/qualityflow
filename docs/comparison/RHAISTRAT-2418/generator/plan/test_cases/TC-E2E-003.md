# TC-E2E-003: End-to-end rolling update resilience

**Objective**: Validate that the full observability pipeline
survives an Authorino rolling update without data loss, spurious
alerts, or dashboard disruption.

**Preconditions**:

- Full observability pipeline operational (TC-E2E-001 passed)
- Auth traffic flowing with stable metrics baseline
- Dashboard showing steady-state data

**Test Steps**:

1. Record baseline values:

   ```bash
   curl -s "https://<prometheus-route>/api/v1/query?query=\
     maas:auth_decisions:rate5m" | jq '.data.result[0].value[1]'
   ```

2. Trigger Authorino rolling update:

   ```bash
   kubectl rollout restart deployment/authorino \
     -n <authorino-namespace>
   ```

3. Monitor recording rule output every 30 seconds during rollout.
4. Verify no `MaaSHighAuthDenyRate` alert fires during the
   rollout window.
5. After rollout completes, verify:
   - ServiceMonitor target is "up"
   - Recording rules produce non-empty results
   - Dashboard stat panels show non-zero values
   - Dashboard time series panels show continuous data (brief
     dip acceptable, no gaps >2 scrape intervals)
6. Verify metrics rate returns to approximately baseline level
   within 5 minutes of rollout completion.

**Expected Results**:

- Rolling update completes without triggering
  `MaaSHighAuthDenyRate` alert
- ServiceMonitor target recovers to "up" within 60 seconds of
  pod readiness
- Recording rules resume producing data after rollout
- Dashboard time series show at most a brief dip, not a
  prolonged gap or negative spike
- Metrics baseline is restored within 5 minutes post-rollout
