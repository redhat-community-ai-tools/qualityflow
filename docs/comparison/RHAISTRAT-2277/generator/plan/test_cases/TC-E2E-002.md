# TC-E2E-002: Greenfield 3.6 routes /v1/embeddings through Praxis to the configured backend

**Objective**: Verify that `POST /v1/embeddings` on a greenfield 3.6 deployment is routed by Praxis
to the configured embedding backend and returns a valid embedding with the expected dimensions.

**Preconditions**:

- Greenfield RHOAI 3.6 cluster with Praxis as the public entrypoint
- An embedding backend reachable from Praxis — a vLLM embedding endpoint or OGX's embedding provider
- The expected vector dimension for the configured embedding model is known and recorded before the
  run, so the assertion compares against a value established independently of the response

**Test Steps**:

1. Record the configured embedding model name and its expected output dimension from the deployed
   backend's model metadata.
2. Send an authenticated `POST /v1/embeddings` request with a single input string through the
   external Gateway hostname.
3. Parse the response and count the elements of `data[0].embedding`.
4. Send a second request with a two-element input array and confirm two embedding objects are
   returned, indexed 0 and 1.

**Expected Results**:

- Both requests return HTTP 200
- `data[0].embedding` is an array of floats whose length equals the recorded model dimension
- The response `model` field matches the requested model
- The batch request returns exactly two objects with `index` values 0 and 1
- `usage.prompt_tokens` is present and greater than zero

**Test Data**:

```bash
curl -sS -X POST "https://${GATEWAY_HOST}/v1/embeddings" \
  -H "Authorization: Bearer ${TENANT_A_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"model": "nomic-embed-text-v1.5", "input": "quarterly migration readiness review"}'
```
