# TC-E2E-004: Write path routes each resource to exactly one backend with no dual-write

**Objective**: Verify that creating a File, a Vector Store, a Response, and a Conversation through
Praxis writes each resource to exactly one authoritative backend, with no logical resource appearing
in two state stores.

**Preconditions**:

- Upgraded RHOAI 3.6 cluster with Praxis fronting OGX
- Write-operation audit logging enabled and collectible for the duration of the run
- Direct PostgreSQL access to OGX's state tables
- If Praxis has its own persistence layer, direct read access to it as well. Which backend owns each
  resource type in a greenfield deployment is still TBD in the strategy, so this case targets the
  upgraded topology where OGX is the documented owner

**Test Steps**:

1. Start audit log collection and record the start timestamp.
2. Upload a file via `POST /v1/files` and capture the returned file ID.
3. Create a vector store via `POST /v1/vector-stores` and capture the returned ID.
4. Attach the file to the vector store and wait for the attachment to report completed.
5. Create a conversation via `POST /v1/conversations` and capture its ID.
6. Create a response via `POST /v1/responses` referencing the conversation, and capture its ID.
7. Stop audit collection and extract every write operation carrying one of the four captured IDs.
8. For each captured ID, query OGX PostgreSQL for its presence, and query the Praxis state store for
   the same ID.

**Expected Results**:

- All four create calls return HTTP 200 or 201 with a non-empty resource ID
- For each of the four resource IDs, the audit log contains write operations against exactly one
  backend — no ID appears in write entries for both OGX and Praxis
- Each file ID and vector store ID is present in OGX PostgreSQL and absent from any Praxis-owned
  store
- The file-to-vector-store attachment reports a completed status rather than remaining in progress

**Validation**:

- `psql -c "SELECT id FROM files_metadata WHERE id = '<file_id>';"` returns exactly one row
- `psql -c "SELECT id FROM vector_store_metadata WHERE id = '<vs_id>';"` returns exactly one row
- The same IDs return no rows from any Praxis-owned state store
