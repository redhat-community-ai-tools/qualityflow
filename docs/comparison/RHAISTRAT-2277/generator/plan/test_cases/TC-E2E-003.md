# TC-E2E-003: Pre-existing file and vector store IDs resolve identically through Praxis after upgrade

**Objective**: Verify that file IDs and vector store IDs created under RHOAI 3.5 return the same
data through Praxis after the 3.5-to-3.6 upgrade, with no change to customer request code.

**Preconditions**:

- Cluster provisioned at RHOAI 3.5 GA with OGX serving the public API
- At least three Files and two Vector Stores created through the 3.5 endpoint, with their IDs,
  metadata, and byte sizes captured to a baseline file before the upgrade
- The same client code and credentials are used for both the pre- and post-upgrade runs

**Test Steps**:

1. On the 3.5 cluster, for each recorded file ID call `GET /v1/files/{id}` and for each vector store
   ID call `GET /v1/vector_stores/{id}`. Save every response body as the pre-upgrade baseline.
2. Upgrade the cluster from 3.5 to 3.6, allowing rhods-operator to reconcile the Gateway and
   HTTPRoute resources.
3. Wait for the upgrade to report complete and for Praxis to become Ready.
4. Re-run the identical requests from step 1 against the same external hostname, changing nothing in
   the client except nothing at all — same URL, same headers, same IDs.
5. Diff each post-upgrade response body against its pre-upgrade baseline.
6. Confirm the responses are now served by Praxis by correlating request IDs against Praxis logs.

**Expected Results**:

- Every `GET /v1/files/{id}` returns HTTP 200 both before and after the upgrade
- Every `GET /v1/vector_stores/{id}` returns HTTP 200 both before and after the upgrade
- For each ID, the post-upgrade response body is byte-identical to the pre-upgrade baseline on the
  `id`, `bytes`, `filename`, `created_at`, and `status` fields
- No file ID or vector store ID returns HTTP 404 after the upgrade
- The client sent identical requests in both runs — no endpoint, header, or payload change
- Post-upgrade requests appear in Praxis pod logs

**Validation**:

- Query OGX PostgreSQL directly and confirm the row count in `files_metadata` and
  `vector_store_metadata` is unchanged across the upgrade:
  `psql -c "SELECT count(*) FROM files_metadata;"`
