# TC-E2E-001: Basic inference with native Anthropic provider

**Objective**: Verify that a deployed RHOAI OGX distribution with
`remote::anthropic` provider accepts inference requests and returns
valid responses using native authentication headers.

**Preconditions**:

- RHOAI 3.5 cluster with OGX distribution deployed
- `ANTHROPIC_API_KEY` environment variable set via Kubernetes Secret
- `remote::anthropic` provider activated in `config.yaml`

**Test Steps**:

1. Verify the OGX distribution pod is running and the Anthropic
   provider is activated by checking pod logs for provider
   registration
2. Send a chat completion request to the OGX endpoint:

   ```bash
   curl -s -X POST <ogx-route>/v1/chat/completions \
     -H "Content-Type: application/json" \
     -d '{
       "model": "<anthropic-model-id>",
       "messages": [{"role": "user", "content": "What is 2+2?"}],
       "temperature": 0.1
     }'
   ```

3. Verify the response contains a valid completion with HTTP 200
4. Confirm no `network.headers` workaround was needed — the
   provider sent `x-api-key` and `anthropic-version` headers
   natively (verify via pod logs or request tracing)

**Expected Results**:

- HTTP 200 response with a JSON body containing a `choices` array
  with at least one completion message
- Pod logs show `x-api-key` and `anthropic-version` headers sent
  to Anthropic API (not `Authorization: Bearer`)
- No `network.headers` configuration present in the provider config

**Test Data**:

```json
{
  "model": "<anthropic-model-id>",
  "messages": [{"role": "user", "content": "What is 2+2?"}],
  "temperature": 0.1
}
```
