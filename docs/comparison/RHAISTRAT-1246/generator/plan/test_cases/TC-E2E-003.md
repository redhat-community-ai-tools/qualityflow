# TC-E2E-003: Per-request API key override via provider data header

**Objective**: Verify that the `x-ogx-provider-data` header with
`anthropic_api_key` field overrides the config-level API key for
per-request authentication.

**Preconditions**:

- RHOAI 3.5 cluster with `remote::anthropic` provider activated
- Config-level `ANTHROPIC_API_KEY` set (Key A)
- A second valid Anthropic API key available (Key B)

**Test Steps**:

1. Send a chat completion request without the override header
   (uses config-level Key A):

   ```bash
   curl -s -X POST <ogx-route>/v1/chat/completions \
     -H "Content-Type: application/json" \
     -d '{"model": "<model>", "messages": [{"role": "user", "content": "hello"}]}'
   ```

2. Verify the request succeeds with HTTP 200
3. Send a chat completion request with the `x-ogx-provider-data`
   header using Key B:

   ```bash
   curl -s -X POST <ogx-route>/v1/chat/completions \
     -H "Content-Type: application/json" \
     -H 'x-ogx-provider-data: {"anthropic_api_key": "<key-B>"}' \
     -d '{"model": "<model>", "messages": [{"role": "user", "content": "hello"}]}'
   ```

4. Verify this request also succeeds with HTTP 200, confirming Key B
   was used for authentication to Anthropic's API

**Expected Results**:

- Both requests return HTTP 200 with valid completion responses
- The second request authenticates with Key B (not Key A), confirmed
  by the per-request override mechanism functioning correctly
- Config-level Key A remains unchanged after the per-request override
